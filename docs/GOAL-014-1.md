## 確認したことと原因の確度

ユーザー報告は「2ステージ目以降は音がなかった」。音楽だけの障害、端末音量、サイレントスイッチ、出力先のいずれかと断定しない。この作業ではiPhoneのAVAudioSessionや実際の出力を直接観測していない。

次の不整合はコードと回帰テストで確認した。

1. 音楽の読み込み失敗がowner全体の失敗処理を呼び、正常な環境音と効果音も解放していた。修正前のテストは10個の正常な効果音・環境音playerが0になることを示した。
2. 旧ownerが停止してから次の音がbufferingしている間、採用版の「再生中playerがなければ100ms後にセッションを非アクティブ化する」条件が成立し得た。共有セッションfakeで再現した仮説であり、今回の端末でこの順序が起きたことの証拠ではない。既に別playerが再生中なら非アクティブ化されない負の対照も保持した。
3. pauseからの再開時、画面が音ownerを有効にする前に修復を要求すると、その要求が正しく拒否され、失敗済みの同じ曲を修復できなかった。実App／Screenの回帰で旧順序が失敗し、有効化後に明示的な再開意図を処理する順序で成功した。
4. クロスフェード先がbufferingしていても元の曲を退場させる経路と、nativeのstatusイベントだけに含まれるエラーがcurrentStatusの読み直しで失われる経路も、個別の失敗テストから修正した。

採用したexpo-audioのSwift実装・型・versionの対応、失敗ログ、回復の範囲は [音声検証記録](AUDIO-TRANSITION-VERIFICATION.md) に記載する。`play()`、statusのplaying、時刻の進行を実聴済みの意味には使わない。

## 音の所有と回復

global activationは共有coordinatorだけが直列に呼ぶ。各ownerはleaseを持ち、古い非同期完了はgenerationを照合する。前ownerのfalseが既に実行中なら、次ownerの準備は後続trueの完了を待つ。管理するplayerすべてに `keepAudioSessionActive:true` を指定し、個々のpause／終了による暗黙停止を避ける。背景、全音オフ、全音量0、最後のowner終了時は共有管理から停止する。

音楽の失敗はそのvoiceに限定し、健康な効果音・環境音を保持する。修復は前景復帰または利用者の再開操作に伴う最大2回。進行・音量・ミュートは変更せず、古い一発音を再生待ちの列に残さない。経路切断の後、毎フレームの音楽要求で勝手に再開しない。音源ごとの一般的なnative API例外をすべてasset不良かbackend全体障害かに分類できるとは主張しない。

音楽は最大2voice、効果音・環境音のpoolは最大10player。無音の維持用音源、画面退出後に残すplayer、毎フレームの再作成は追加していない。消音スイッチ尊重、録音なし、背景再生なしを維持する。6曲・15物理音・従来7音源の素材は変更しない。

診断はversion1の最大64イベント、独立したfirstAudioFailure、現在owner／player／共有セッションの状態を持つ。先のGL FIRST_FAILUREを上書きしない。明示的なサポート操作でだけコピーし、URL、認証値、不要な個人情報を除去する。送信・録音・新しい権限は追加しない。

## 通常の表示とサポート

通常のホームからbuild／code／profile表示を外した。準備は「画面を準備しています。」、失敗は「画面を表示できませんでした。」、音は「音楽／環境音／効果音」、触覚は「振動」とする。保存の案内は実際の保持・消去・安全再開の意味に合わせる。内部のキーや分類ID、保存codecは変更しない。

`設定 → サポート → 詳しい情報 → 情報をコピー` から `goal-014-1-audio-ja-r1` を確認する。画面失敗からも詳細を開ける。初期状態では閉じ、閉じるとraw情報は表示と読み上げ対象から外れる。previewは `__DEV__=false` でも完全なローカル診断を取得でき、productionは必要なアプリ情報と障害要約を明示コピーできる。開発用の道具はDEVだけの明示経路に置く。

旧文、新文、表示条件、3D掲示、権利・正式名称の例外は [文字監査](PLAYER-TEXT-AUDIT.md) に記載する。日本語の長いボタンが小さい幅・文字拡大で親より広くなる問題には、共通ボタンの最大幅を親の100%に制限して折り返す変更を加えた。クリック領域の最小高さは保つ。
