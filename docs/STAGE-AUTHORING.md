# Stage Kit v1: chapter authoring

Run `node scripts/create-stage.cjs --help`, then use `--id safe-slug --title "表示名" --dry-run` to inspect the generated paths. Remove `--dry-run` to create the development-only folder. The command rejects existing directories and unsafe slugs; it never edits a player card, package dependency or external service.

The generated `definition.ts` owns the floor, physical door, target locations and named safe poses. `session.ts` owns the independent mutable run, command sequence and puzzle state. `checkpoint.ts` parses unknown data before a session can be created. `binding.ts` adapts that state to the existing first-person frame owner and codec. `scene.tsx` draws the same world; `stage.test.ts` exercises the authored device and door. Do not treat the generated room as a finished chapter.

To run it inside the existing host, add the stage metadata and its target IDs to `src/domain/stageKit/definitions.ts` with `playerVisible:false`, bind the module in `src/domain/stageKit/modules.ts`, and add its scene to `src/rendering/firstPerson/stageSceneBindings.tsx`. Keep the save key stable across text and presentation revisions; raise `contentVersion` independently of the checkpoint's `schemaVersion`. Do not display an unfinished stage to players. Run `node scripts/validate-stage-definitions.cjs`, the stage's test and the controller route test before considering promotion.

For a playable release, finish the artwork, result text, accessibility interaction and content, then set `playerVisible:true`. A `simple` module uses the generic App and AsyncStorage fallback; its binding must implement `canReplaceCheckpoint` so a resumed run cannot silently lose confirmed progress. The four old public checkpoint namespaces retain explicit migration code. A chapter with a different render kind or new save semantics still needs its own composition work. The hidden probe now proves controller, renderer, codec and generic AsyncStorage in separate tests; it is not a production-ready fifth card. Never repurpose another chapter's save key.

Use one world for collision, ray acquisition and rendering. Author safe entry and resume poses on that world, including each closed-door state. A passing static graph does not prove the route: run the actual controller from entrance through the device, door and exit, cold restore the checkpoint, and verify two sessions from one checkpoint do not share mutable state. Review every target's label and VoiceOver action. The stage may return a custom `inputPolicy`, but it must not create its own render loop or renderer. Gallery and the old entrance remain compatibility paths in this version.
