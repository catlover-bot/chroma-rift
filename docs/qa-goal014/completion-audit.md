## Findings and corrections

1. **Outdoor aftermath originally froze movement. Fixed during this review.** `completionTailMovement` is an optional Stage Kit contract enabled only for area05. The four-second completed tail accepts ordinary walking and looking against the same world collision. Device actions stay closed, the actor does not advance, and the saved completed checkpoint stays unchanged. Player step audio can still follow successfully presented movement. Simple controls and normal touch controls use the same permission. Pause/background retain their existing stop boundary. A focused actual-screen/controller test checks movement, look, blocked interaction, unchanged checkpoint, paused time and once-only expiry.
2. **Ratchet SE had no corresponding per-tooth haptic. Fixed during this review.** The screen initializes its observed integer count from the cold checkpoint, then queues one haptic per newly published tooth through the existing presentation-feedback owner. No haptic is generated by speculative simulation alone, repeated publication, or an already saved tooth. Haptics-off remains off. A real held-controller sequence verifies cold count 1, rejected-frame rollback, displayed counts 2/3 and exactly-once calls.
3. **Containment door's glass and its sight volume disagreed. Fixed after this review.** `containmentDoor.ts` now supplies the same authored pane, steel and mullion bounds to the actual scene and sight volumes. The original full slab remains solid for player/actor bodies, while only its rendered steel, mullions and seal block sight. The same door progress translates both. Eye-height rays distinguish glass from steel at open, closing and closed positions; actual rendered mesh bounds are compared with world solids, and body collision remains equivalent to the old slab. No actor/FOV/radius changes were made. The fixed observation panes are separate from this moving pane.
4. **Large action labels exceeded the two-line button allocation. Fixed during the final capture audit.** Browser glyph-range checks found five area04/05 labels at 320×568/fontScale2, in both quality modes, with 107.19 px text height inside a 104 px action button. The text remained inside the viewport; the earlier visual suspicion of viewport clipping was not confirmed by measurement. `controlLayout.ts` now reserves three enlarged lines plus padding, and the same layout moves the explanation and touch region. FontScale1 stays unchanged; no label, prerequisite reason or font scaling was removed. The capture gate now checks actual text ranges as well as button rectangles, with a 1 CSS px rounding allowance. These remain CSS measurements, not native Yoga acceptance. A red layout regression became green; **4 suites / 31 tests PASS**, TypeScript and targeted ESLint PASS, in `.expo/goal014/logs/hud-three-line-{green,types,lint}-final.log`. The actual Screen regression retains the long disabled label/reason and verifies the adjusted touch/context placement. Final source-matched captures are linked from [scene/HUD QA](scene-hud/README.md).

## Scope limits

The review inspected two full-resolution scene/HUD images (04 holding and 05 call bell) and the actor/audio measurements; it did not continuously watch every movie or listen to the files. CSS/native readiness fixtures, software WebGL, real controller/state execution and native-device behavior remain separate evidence classes. A green unit suite cannot close subjective art, sound or first-time comprehension acceptance. Conversely, those permitted pending evaluations must not be used to omit real game integration, required local artifacts or the final local checks.
