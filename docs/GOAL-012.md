# Goal 012: Stage Kit v1 implementation record

The working base is local HEAD `5c04d98` on `fix/goal-010-1-stage-boundaries`. Work is on `feat/goal-012-stage-kit` in the linked worktree. The original checkout was clean and remains on its original branch. Goal 011's mirror chapter is absent from this local HEAD; no mirror code was deleted or inferred from a roadmap entry. The protected package, Expo, EAS and Metro files have the same SHA-256 values as in `GOAL-012-BASELINE.md`.

The static catalog in `src/domain/stageKit/definitions.ts` now derives the four player cards and the stage/target ID types. `modules.ts` binds theatre and vault creation, update, world, presentation, commands and checkpoint codecs; gallery has a compatibility binding and the entrance stays on its validated legacy path. The first-person host calls these bindings where practical. `ChapterRuntime` still has old optional chapter fields, so this is an adapter stage, not a full discriminated-session rewrite. The hidden `stage-kit-probe` shows a typed module, one device, physical door, scene binding, exit and checkpoint/cold restore without a probe-specific branch in the common controller or renderer.

The shared one-axis drag helper is used by the theatre light rail and vault length clasp. The optical and length success rules remain separate. Two bells in the live theatre have separate input plates, remote sound receivers and cooldown states. Accepted commands emit domain noise at each receiver; the existing AI must hear and route to it. The manual shutter has two handles and one open/closed progression used by visual mesh, LOS and collision; closing is rejected while a player or visible actor occupies its sweep. Bells and shutter are optional and transient. Pause preserves cooldown and shutter position within a session, while a cold checkpoint resume resets them. No theatre checkpoint schema or required exit condition changed.

The limited `TheatreCue` path is used by bells, shutter and projector. Its local audio is flushed only after a presented frame and dropped on stop/pause/failure; it does not inject hearing into AI. The developer diagnostic panel now includes stage ID/version, session/revision, target, input policy, blocked reason, objective, last theatre command, actor memory, pending noise and render/resource counters. It has no remote analytics.

`scripts/validate-stage-definitions.cjs` runs a validator over the same constructors, worlds and codecs used by play. It checks catalog duplicates, stage/module mismatch, geometry numbers, spawn safety, target registration, action IDs and bell receiver/shutter references. `scripts/create-stage.cjs` creates a hidden development room and refuses unsafe slugs or overwrites. `STAGE-AUTHORING.md`, `GIMMICK-AUTHORING.md` and `GOAL-012-EXTENSION-PROOF.md` record the authoring route and what it actually proves.

## Evidence and limits

Baseline `npm run test -- --silent` on the untouched base ran 90 suites/1,036 tests with one theatre route failure and 1,035 passes; the route passed when rerun alone. The first broad `npm run check` after implementation ran 94 suites/1,044 tests with 1 failed gallery codec test and 2 scene-boundary tests; those were corrected. The next broad run had 1,043/1,044 passing and a single theatre Screen acquisition failure that passed immediately in isolation. A later broad run after the generic App/storage route had 1,045/1,046 passing because one gallery VoiceOver adjustment test failed; the same test passed immediately alone and in the final broad run. Final `npm run check` passed 95 suites/1,046 tests, lint, typecheck and iOS export. No test was skipped or loosened to hide these failures.

Seven local MP4 clips and source hashes are in `qa-goal012/`. They use actual Screen/controller/scene output, 60 Hz simulation and software WebGL capture. They show the light input, A/B receiver response under a declared actor comparison setup, the shutter, a full route without the new devices, a full subdued route using bell A and the shutter, and App pause/reentry across chapters. An extraction-only route matrix also completed all eight no-device/bell/shutter/both combinations under standard and subdued intensity with the actual controller and scene. The probe App path has two extracted frames. There is no pre-migration video comparison, no native iPhone capture, and no actual listening or fear evaluation. The iPhone steps are appended to `IPHONE_VALIDATION.md`. Software WebGL draw calls are not iPhone performance.

The hidden probe's save/restore proof uses both the host checkpoint codec and the generic AsyncStorage writer/loader. The public `App.tsx` has a generic selection, run, reset and save fallback for future visible `simple` modules; the four old namespaces retain explicit compatibility and migration logic. A controlled QA process temporarily exposes the probe only in memory, exercises actual App selection and a device interaction, unmounts App, then cold re-enters from isolated in-memory AsyncStorage with its physical door still open. The product build still has four cards. A new render kind or chapter-specific result/artwork still needs composition work. Stage Kit v1 is not a one-line arbitrary chapter engine. Native files and dependencies did not change, so this work does not itself require a new native binary, but compatibility of an installed device binary was not tested.
