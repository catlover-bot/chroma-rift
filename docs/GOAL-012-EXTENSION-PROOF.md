# Goal 012 extension probe

The base checkout had four playable chapters and no Stage Kit probe. `node scripts/create-stage.cjs --id stage-kit-probe --title 'Stage Kit 確認室' --dry-run` listed paths without writing them; the same command without `--dry-run` created `src/domain/stages/stage-kit-probe/{definition,session,checkpoint,binding,scene,stage.test,README}`. An unsafe `../` slug was rejected, and the generator refuses to overwrite that folder.

Registration changed three explicit composition points: `src/domain/stageKit/definitions.ts` (metadata, target IDs, `playerVisible:false`), `src/domain/stageKit/modules.ts` (typed module), and `src/rendering/firstPerson/stageSceneBindings.tsx` (scene component). The generic `ChapterScene`, `FirstPersonCanvas`, `firstPerson/runtime`, `chapter` and `checkpoint` interfaces were prepared for a `simple` render binding as foundation changes. No probe-specific branch was added to the common controller, renderer or interaction evaluator; a generic target label fallback is used. The player stage list still has four cards.

The generated domain test and `stageKitProbeController.test.ts` exercise fresh entry, the real controller target, activation, the lifted physical door, walking to the exit, checkpoint creation and cold restore through the module codec. The test also checks that two sessions do not share the checkpoint's pose reference. `moduleStageStorage.test.ts` writes that checkpoint through the generic AsyncStorage route, cold-loads it under its own key, rejects a rewind and foreign checkpoint, preserves an unknown-version raw document, and backs it up before explicit reset. `validateDefinitions.test.ts` runs the same constructors/world/codecs used by play.

The `--probe-visible` mode of `scripts/preview-chapter-reentry.cjs` temporarily flips the in-memory catalog flag only inside that QA process, before App imports its catalog. It follows actual App selection and preparation, enters the probe, dispatches the real controller device interaction, records a write to `chroma-rift.dev.stage-kit-probe.v1`, pauses and returns home, unmounts App, mounts a fresh App over isolated in-memory AsyncStorage, then re-enters the same probe. The second App sees `activated:true` and a door collider raised to `y=3.6`; at most one Canvas boundary was active. The source files still register the probe as hidden. The independent controller test completes the exit. This is a controlled host integration proof, not iPhone/Yoga/real-storage validation or a finished player fifth chapter. Custom render kinds/content still require composition work.
