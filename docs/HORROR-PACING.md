# Goal 008 — 予期、提示、回避と回復

この文書は `feat/goal-008-perceptual-horror`、基準 `8ca5ba3456c7f54284981e9cae1b0d5a8848b21d` から追加した実装の設計と検査記録。怖さ、気づきや錯視の成立を測定した報告ではない。

## 実装順と確認ゲート

- 変更前に親担当が 56 suites / 674 tests、lint/typecheck/iOS export を含む check、Doctor 21/21 を確認した。
- phase B は実凹面メッシュの正面・側面と、一枚のハイブリッド画像の近中遠を実WebGLで確認した。[素材QA](qa-goal008/materials) の通過連絡まで、新配線は純domain・保存parserだけを先行した。
- phase C で配線、旧B/C両順、旧firstPerson domainの **7 suites / 131 tests PASS（3.75秒）**。その後、実controllerの両順を控えめ設定で実行し **2件 PASS（2.668秒）**。この時点では既存FSMが動作し、AI全体のmockや敵非表示で通していない。標準4件は削除せず、phase Dで全6経路を検査した。
- phase D では同じ個体の横切り、実身体の衝突、新経路の追跡とlastSeen捜索を追加した。担当範囲47件（gallery22、配線7、actor12、実controller6）を通過した。全アプリ集計は [GOAL-008](GOAL-008.md) を参照。

## 一つの個体と静止展示を分ける

仮面は `mask-exhibit`、動く展示体は `gallery-exhibit-actor` の別IDとtransform。仮面のworld変換・頂点・法線は歩行で変えない。検査窓だけが同じ保存状態に応じて1.6m上がる。掲示は `hybrid-exhibit` の一枚の固定texture/UVを使う。どちらの見え方も敵のcollisionや正解条件に転用しない。

動く展示体の初期足位置は `(-.55, 0, 9)`。初めから同じ立体があり、最初の電源で別モデルへ置き換えない。前面・移動・LOSは共通のlocal `-Z`、yaw 0はworld `-Z`。歩幅 `GALLERY_ACTOR_STEP_DISTANCE=.48m` は造形と音が共有する。敵は9 waypoint、最大12という範囲に収まる。

## 開口、保守ベイ、手書きの回避経路

閉じたサービス格子は縦棒x `[-.94,-.7,.7,.94]` と横棒y `.85..95 / 2.65..2.75`。自然な戻り位置 `(0,1.6,2)` から停止点の頭・肩への実LOSを通し、腰の横棒でプレイヤーの通り抜けを防ぐ。すべて同じdoor stateで上がる。

保守ベイは `x=-6..1,z=6..13`。配線板中心 `(-5.78,1.75,9.8)`、観察位置 `(-1.2,1.6,9.8)`。配線を明示接続すると、主通路の `z=11` シャッターと、ベイ→西棚側の `x=1,z=10..13.06` の扉が同時に開く。

実controllerで通した経路:

```text
B/C両順 → 出口盤 (0,2) → 敷居 (0,7)
→ 保守ベイ (-1.2,9.8)で配線
→ (-1.2,12.5) → (1.7,12.5) → 西棚陰 (1.7,13.8)
→ 巡回が北へ過ぎるのを待つ → (1.7,15.2) → (4,15.2)
→ (4,17.5) → (6.3,17.5) → 東棚陰 (6.3,18.8)
→ 巡回が北へ過ぎるのを待つ → (6.3,20.5) → (4,20.5)
→ 安全敷居 (4,24) → 明示閉扉
```

西棚は `x=2.7..3.15,z=13.2..14.4`、東棚は `x=4.85..5.3,z=18.2..19.4`、高さ2.45m。安全性は名前だけで決めず、同じworldの不透明な棚、敵の専用0.44m衝突半径、移動禁止領域とLOSで確認する。動的な `gallery-actor-body` はプレイヤーの通常移動にも衝突するため、猶予や控えめ設定でも身体を通り抜けない。控えめでは同じ個体が脇の `(4.4,21.3)` へ歩き、追跡・接触復帰を行わない。

標準B→Cでは、巡回が北向きに近づく時に西棚の南端 `(4,12.5)` へ出て、**noticed→approach** を実際に起こし、棚陰へ戻って **search→patrol** になるまで待つ。同じcontroller走破の中でphase履歴、棚の実LOS、lastSeen固定と捕獲されずに待てることを検査する。単に全通路を走り抜けた結果を追跡回避の根拠にしない。

## 操作・保存・停止の境界

配線はローカル座標の固定線 `y=m*x+b` と可動線 `y=m*x+b+offset`。40°、初期offset .24m、許容差 .028mは今回の著者設定で、知覚的な最適値とは主張しない。カバーは水平位置だけを `-.97..0` で動かし、線・正解は不変。指を離すまでlive値、外drop/cancelで確定値へ戻し、「接続する」でのみ開通する。

保存はlevel/schema v3。同じlogical galleryでv1/v2を厳格に読み、旧接続済み・終盤・clearedは配線を `compatibleBypass=true` で開通させる。新規開始では配線未解決。互換通過・発見・カタログ登録は別々で、新しい発見と横切りの提示bitを移行で捏造しない。lastSafePoseの生データを別writerで保存せず、認可済みcheckpointのposeとして保存する。巡回の時刻、touch、音・GPU資源は保存しない。 最後の敷居を実際に訪れた後で通路へ戻った場合も、接触復帰と保存再開は同じ最終安全checkpointを使う。接触で扉を閉じたり、発見・未提示のstoryを追加したりせず、閉扉は引き続き明示操作だけで確定する。

pause/background/GL未準備/装置操作/メモ中は進行を止め、再開時は同じ位置から猶予を置く。domainのdt上限は0.25秒、実controllerの移動/AI入力は最大0.05秒で、長い中断分を一括実行しない。提示に失敗したframeのruntime（敵・story bit・安全地点を含む）と音・字幕は親のnative sessionでrollback/破棄する。
