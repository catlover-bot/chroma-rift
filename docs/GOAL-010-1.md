## Part A — 実行時依存の方向

基準版を `git archive` で作った作業ツリー外の固定コピーを走査した。表示された10経路は重なりがあり、全アプリの実行時グラフでは **18 modulesのdomain SCC + 4 modulesのcontroller SCC = 2群** だった。変更後は **0群**。

| 所有する定義 | 移動前 → 移動先 | 意味 |
|---|---|---|
| EYE_HEIGHT / PLAYER_RADIUS / PLAYER_HEIGHT / FOV / camera near・far / floor・ceiling寸法 | chapter → firstPerson/constants | 数値をそのまま単一所有 |
| 旧章定義、KEY_FRAME / KEY_FRAGMENTS等 | chapter → firstPerson/legacyDefinition | 他章を読み込まず旧章の定義を初期化 |
| box / boundaryWalls | chapter → firstPerson/boundaryWalls | 純粋な境界形状生成 |
| ACTOR_COLLISION_RADIUS / ACTOR_MODEL_BOUNDS | gallery/actor → actorMotion/envelope | 行動・進行に依存しない身体境界 |
| occlusionCertificate | runtime → firstPerson/occlusion | 全8頂点・同一opaque壁の証明式を保持 |
| VAULT_AI / vaultActorEdgeOpen / vaultNoiseAudibility | vault/actor → vault/actorPolicy | worldを受け取る既存判定・全数値を保持 |
| initialProgress / emblemCheckpointForProgress / session counter | runtime → firstPerson/baseRuntime | 章選択に戻らない共通初期化 |
| RuntimeController / RuntimeSnapshot | runtimeController → controllerTypes | type-only、実行時初期化なし |

| soundForControllerTransition | runtimeController → controllerTransitionAudio | 受理済み遷移から同じ音イベントを分類 |

galleryは自分の純粋なworld builderを参照する。gallery/vault/theatreの直接constructorはbaseを一度だけ作り、章dispatcherへ旧章のテンプレートを求めて戻らない。公開互換exportは残し、内部は葉モジュールを参照する。セッションカウンターは全constructor共通で、明示sessionの最大値にも追従する。

依存方向は「型・数値・純粋geometry・base状態 → stage world/behavior → 章dispatcher → controller orchestration → UI」。world更新を避ける固定cache、遅延require、registry、警告抑制を導入していない。top-levelのKEY_FRAME/KEY_FRAGMENTS/staticWalls、gallery/vault固定collider、INITIAL_CHECKPOINTが循環の途中で未初期化値を受けない方向にした。

境界変更に伴う限定的な修正として、保存progressのnested object/arrayをcold constructorでコピーした。元の浅いコピーでは同じcheckpointから作る別セッションが可変状態を共有していたため、「保存復元でも独立」という受入条件を満たす。保存値・schema・正解条件の変更ではない。4章それぞれの初期runtime/world、checkpoint、復元runtime/worldのJSON値は明示sessionを固定して基準版と一致し、checkpoint/A/Bの可変参照集合も交差0だった。

## Part B — 表示と操作状態

受光窓の判定領域・rail/source・coat triangles・投影・許容coverageは変更していない。実窓の外側へ中立色の構造枠、1（左）/2（右）の番号、光/影の形状表示を置いた。番号はHUDと同じ定義を参照する。`theatreLightStatus` はcommitと同じ `evaluateLight` から0/2と各窓状態を作り、drag release済み・保存rail一致・canLockが揃った場合だけ「灯りを固定して扉を開く」を有効にする。

短いdrag案内は実rail移動を伴う内側releaseでのみ消え、timeout・空タップ・cancelでは消えない。保存schemaは変えず、一度解放した進行を戻さない。解放後は任意観察として表示し、再固定ボタンを出さない。

元のwall/floor/receiver/shadow材料の色を保ち、別の中立色材料で壁際の足元線・棚/partitionの端・通路枠・少数の床印を足した。制御室は二本線、保守口は工具形の目印で区別する。これらは描画だけでcollider/通路幅/Ames/equal-size props/FOV/roll/depth処理を変えない。追加renderer/GL context/texture/postprocess/shadow mapはない。追加材料とinstanced meshは既存scene lifetime内でdisposeする。

projectorの操作待ち、起動直後、作動中、停止後の再使用待ちを分ける。状態は実motor/noise timerから取り、音声playerの再生成功を敵の誘導成功とは呼ばない。回転ハンドルとreelの既存動作を保持する。実装上は5秒作動と合計6.2秒の再操作待ちを同時に始めるため、停止後1.2秒で再使用できる。速度・聴覚・chase・接触・経路・horror modeは変更しない。重複した新sequenceのarmだけは既にarmedなら拒否し、途中の回転量をリセットしない。

## Part C — 残る警告

インストール済みR3F 9.7.0のnative entryが読む `dist/events-b1bdeb1a.cjs.dev.js` のcreateStore（1041行）が `new THREE.Clock()` を生成し、Three 0.185.1のconstructorがdeprecated警告を出す。アプリからの直接生成ではなかった。R3FはgetDelta/start/stopだけでなくelapsedTime/oldTimeも更新するため、Timerへの機械的置換は行わない。[Clock](https://threejs.org/docs/pages/Clock.html) と [Timer](https://threejs.org/docs/pages/Timer.html) のAPI・lifecycleは異なる。複数の警告数だけで同時rendererの重複とは判断しない。

ThreeのWebGLTextures → WebGLState → gl.pixelStoreiという実経路を調べ、実アプリ8 DataTextureをbrowserの単一rendererにuploadして、引数を記録しつつ元関数へ渡した。trace終了時にwrapperを復元し、texture/geometryは0へdispose、GL errorは0だった。

| 実browser呼び出し | 値 | installed EXGL pixelStoreiの分岐 |
|---|---:|---|
| UNPACK_FLIP_Y_WEBGL (37440) | false | 対応 |
| UNPACK_PREMULTIPLY_ALPHA_WEBGL (37441) | false | 未対応warning分岐 |
| UNPACK_COLORSPACE_CONVERSION_WEBGL (37443) | 0 | 未対応warning分岐 |
| UNPACK_ALIGNMENT (3317) | 1 | 対応 |

中央2引数は録画の2警告を説明し得る**候補**であり、元iPhoneの実警告引数を採取した結果ではない。対象textureはopaque RGBA・明示sRGB・false flipY/premultiplyで、一部のsourceは行を明示反転する。nativeでの向き・alpha・色を確認したとは言えず、無害とも断定しない。[Expo GLのnative制約](https://docs.expo.dev/versions/latest/sdk/gl-view/) も踏まえ、端末での見え方・実引数・owner/context IDを追加確認する。暗い壁の原因をこの警告へ結び付ける証拠はない。

警告抑制、pixelStorei no-op、Clock差替え、依存更新は行わない。[MetroのrequireCycleIgnorePatterns](https://metrobundler.dev/docs/configuration/#requirecycleignorepatterns) は警告表示の設定で、依存修正の代わりではない。[Nodeの循環の説明](https://nodejs.org/api/modules.html#cycles) は部分初期化の理解に使い、NodeとMetroの起動を同一視しない。
