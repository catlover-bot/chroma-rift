# Stage Kit v1: device authoring

An `ActionInstance` has a stable `instanceId`, a kind, a cooldown and an explicit input policy. Add a second bell by adding a definition with a different ID, physical panel and receiver, then allocate its own `ActionState`. The theatre A and B bells use the same command rule but have separate cooldown and activation counts. A new device kind needs its own evaluator and presentation; do not force optical, length or rotation puzzles through a generic submit rule.

For a one-axis device, use `beginLinearDrag` and `previewLinearDrag` in `src/domain/stageKit/linearDrag.ts`. The pointer ID and starting grab offset stay with the drag; the preview is clamped to the authored range. The controller releases, cancels or submits according to the stage's policy. Theatre light and vault length now share this transport rule. Their light-window and length evaluators, accepted values and saved flags remain chapter-owned. Keep a baseline input trace for preview, release, cancel, edge values and a second grab before changing a live evaluator.

For a bell, distinguish the plate the player faces from the receiver that emits the noise. The accepted controller action creates domain noise at the receiver; the actor's existing hearing and path logic decides whether it investigates. A local `TheatreCue` schedules optional audio after a successfully presented frame. Audio playback never tells the actor that it heard a sound. Pause, background, scene failure and retire discard unpresented cues. Keep UI readiness, command validation, distance, occlusion, session and sequence checks in agreement.

The manual shutter uses one transient open/closed value and one transition progress for its visible slab and collision/LOS volume. Check both handles and the occupied sweep before closing. Reopening from the far side must remain possible. The two bells and shutter are optional: they do not change the theatre clear predicate or checkpoint version. A cold resume raises the shutter and resets bell cooldown; same-session pause retains both. If a future device must persist, save a settled state and validate its checkpoint against a safe pose before restoring.

Run `node scripts/validate-stage-definitions.cjs` after any authored change, then the controller route and scene QA. For a second instance, check its own input, sound source, actor destination, cooldown, cue and pause behavior, and assert that the first instance's state is unchanged. For a new kind, also verify rejected commands, movement policy, available label, VoiceOver equivalent and no new renderer or frame timer.
