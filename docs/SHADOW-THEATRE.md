# 03 影の映写室 — Goal 010

## 目的と操作（仕掛けの答えを含まない）

「影の映写室」は、光と部屋の奥行きを確かめながら退出経路を探す一人称ステージ。既存の移動・視点操作と、目の前の取っ手を押す／ドラッグする操作を使う。任意の点検歩廊と発見メモは、進行に必須ではない。ステージ選択から新規開始／再開でき、他の章の現在進行・設定は別に保つ。

最初の目的は「灯りを動かし、2つの受光窓に光を届ける」。窓は色だけでなく明暗と印で状態を示す。両窓が灯っても、自動では装置を固定しない。「灯りを固定する」を明示操作する。光源の小刻みな調整、段階ヒント、通常の一時停止が使える。映写機の素早い操作は敵の時間を止めない。

6–10分は設計目標で、初見プレイヤーの所要時間は未測定。自動走破時間をプレイ時間や恐怖の強さとして扱わない。

## 安定した章と保存の境界

- ID: `shadow-theatre-v1`、保存キー: `chroma-rift.shadow-theatre.v1`、level/schema/spec version: `1`。
- 実装: `src/domain/theatre/`。既存 `createInitialRuntime/getWorld/evaluateRuntime/interact/createCheckpoint` が型付きで委譲し、別の移動controllerやrendererを作らない。
- 保存する値は seed、確定済みrail・受理・試行数、点検窓と保守戸の状態、明示発見 `shadow/depth`、離散story、幕受理・封鎖・退出完了、最後に訪れた認可済みcheckpoint。
- pointer・掴み位置・preview・回転中の映写機・音owner・敵の時計や記憶は保存しない。ドラッグ中のcheckpointは指を離す前のrailを保持する。
- 通常のpause/background復帰は同じ敵位置・記憶・タイマーを保つ。cold復帰だけは認可済み地点と3秒の猶予から始める。保存の未知version、不正な進行の組合せは厳格parserで拒否し、storage側が原文を保持する。
- checkpointは入口、映写機ベイ、制御室、退出後の4地点。通路の任意座標は保存しない。不正poseから未訪問の下流地点を与えず、幕の受理／完了自体が証明する制御室／退出後だけを復旧先に使う。
- 章の再開始は現在runを置き換える。過去の明示発見・クリア歴はstage journalが別に保持し、他章の保存を置き換えない。

## 光学の共通データと数値検査

`lightGate.ts` の一つの独自コート輪郭を22個の非重複三角形へ分割する。小道具のcast面と影の投影が同じ `COAT_TRIANGLES` を使う。重ねた半透明影を足し合わせず、受光面に切り取ったpolygonを不透明で描く。動く脅威とは別の静止小道具である。

canonical model は `L(s)=(1.5s,1.1,1.2s)`、`s∈[-1,1]`、小道具面 `z=2`、受光面 `z=6`。点Pからの投影は `t=dot(n,Q-L)/dot(n,P-L)`、`S=L+t(P-L)`。平行、光源が面上、非有限値、物体が受光面より後ろなどは無効にして、窓を誤って明るい扱いにしない。world変換は固定scale `.55` と offset `(-1.4,.65,0)`。レール全長は約2.11m、小道具のcast輪郭は高さ.539m、初期投影の高さは未clip時1.617m、受光面でclipした後は1.4135m。

受光窓はcanonical幅.26×高さ.30、中心x±.55/y1.2。正面から見た左右のラベルに合わせ、negative X側は `right`、positive X側は `left`。各窓矩形へ各三角形をclipした面積の和から遮蔽率を得る。許容2%は製品上の操作余裕で、視覚能力の閾値ではない。表示の `lit` と固定可能判定が同じ結果を読む。

2,001点のrail sweepでは初期両窓100%遮蔽、成功区間は `[-1,-.748]` と `[.492,1]`。端の一点に合わせる必要はない。独立の有限ray–triangle oracle、窓中央には当たらない細い3%遮蔽、特異点、受光面clip、world scale変換を検査した。担当外のThree.Ray独立検査は最大面積差約.00104を記録している。ソフトウェアQAの詳細は [qa-goal010](qa-goal010) を参照。

同じrailではdeep-frozenの1件cacheを返す。カメラ・画質・UIの比較補助は光学判定の引数に含めない。rendererもrailの変化時だけ既存bufferを更新する。実handleの画面上44 logical pt領域はcontrollerが検査し、domainの有限hit上限.55mは、その投影補償を受け入れる防御上限。物理レール・小道具・正解を拡大する値ではない。

## 任意の奥行き展示

`perspectiveExhibit.ts` は参照eye `E=(0,1.6,0)`、参照箱 x±1.1、y=.4..3、z=4..6を定義する。各頂点を `E+t(P-E)`、`t=5.2/(6-1.7*P.x)` へ移す。全頂点が元のview ray上に残る射影変換なので、参照位置での箱の投影が元の直方体と一致する一方、実際の後壁は `z=5.2+1.7x`、床と天井も斜めの平面になる。単に一方の人形を遠くへ置いた平らな部屋ではない。

6面の共面性、外向きwinding、12辺の閉構造、有限な頂点を検査。実後壁の深さ比は約1.906、両端の床高差は約.718m。前面と右側面は開口枠として描き、側面の遮蔽だけを実shutterが変える。展示全体は非歩行volume、観察者は外の平らな床に立つ。この歩廊自体は無敵領域ではなく、開いた接続部では通常の視認・追跡・接触が成立する。発見メモを開いた時だけ通常のpauseを使う。

静止2propは同じ `AMES_PROP_PARTS` の3box、同じ `.22×.82×.22m` boundsとworld scale 1。正面投影の高さ比は約1.605で、観察中にmesh、scale、FOVを変えない。実画像を見た後、側面位置を `(-11.45,1.6,10.3), yaw=-.6,pitch=-.12`、中間位置を `(-4.3,1.6,7.45), yaw=1.5` に調整し、両propと歪んだ構造を同じportrait画面へ入れた。中央の側面位置から両propが同時に入るという初期想定は棄却した。

窓を開くだけでは `depth` を記録せず、側面の構造を実対象として調べた時に記録する。窓開放で保守取っ手の実coverも上がり、取っ手の別操作で短い保守通路を開く。通路を使っても発見を自動付与せず、光のゲートも迂回できない。

## 敵、音源、実際の退避

Goal009と同じ接地motion、実head視線、半径.44mの身体、音の距離減衰／壁減衰を再使用。既存vaultの速度や条件は変更していない。Theatreは9 waypointの閉ループで、各edgeを実world collisionに照合する。

光のゲートを通って `z>4.4` へ出ると、同じ一体が `(2.8,0,6.55)` から横切る。cameraが向くまで待たず、見逃しても先へ進む。`crossingPresented` は一致する実cameraとLOSで提示された可能性を記録するだけで、知覚の成功を意味しない。横切り後には猶予を置き、認識.45秒、気づき.65秒、windup.75秒、固定位置への短い攻撃.42秒、回復.95秒を使う。隠れた現在位置を追わず、実際のlastSeen／lastHeardへ移動・捜索し、巡回へ戻る。控えめ設定には追跡・攻撃・接触リセットがない。

入口の開いたゲートには幅.76mの実固定jambが残り、映写機区画の2入口は幅.70m、保守通路と制御室入口は幅.76m。player直径.48mは通り、actor直径.88mは通れない。最初の実験だけでなく戻ってきた時も、見えない安全flagだけに頼らない。

映写機を選んでもmodeは `explore` のまま。取っ手の実角度は `projectorAngle`、指の角度差から更新し、掴み端のoffsetで飛ばない。ドラッグ取消は開始角へ戻り、音を出さない。ドラッグ／読み上げ向け刻み操作とも累計.8π radで受理し、5秒のmotorとその後1.2秒のcooldownがある。音は物理位置 `(-5.37,1.3,15.8)` から発生し、muteでも同じgame-domain evidenceになる。壁越しの減衰や距離によって聞こえない操作もあり、見ているプレイヤーを無条件に忘れさせない。

実controller対照は自然に到達した保護ベイで、同一のruntime・敵の記憶から分岐した。操作しない側は巡回を継続し、聞こえる位置で回した側は実映写機位置を調べた。3.5秒待って下側入口から別の通路へ離れ、幕と出口まで歩いた。単にmotor flagが立ったことを囮の成立としていない。

## 明示した幕の操作と退出

制御室で実取っ手を向き「防火幕を下ろす」を押すと `curtainAccepted=true` をメモリ上で即確定し、非同期保存を要求する。これは保存成功の保証ではなく、保存失敗や未知版rawによる書き込み保護は通知する。プレイヤーは保護側にいる必要があり、actorの身体が幕の掃引volumeにある場合は拒否する。幕は1.05秒で下がり、描画とcollisionが同じopennessを使う。閉じ切って初めて `passageSealed=true`。

全開の幕は頭上にある。保護された床内で少し下がると、取っ手と幕の降下を一緒に見られる。描画QAでは実歩行で `(0.7,1.6,22.25)` へ到達し、390×844の縦画面で実Screen操作→下降→閉鎖→出口を記録した。これは自動カメラ移動や新しいワールドではない。

その場ではまだクリアしない。プレイヤーがさらにサービス出口 `z>=23.3` まで歩くと `completed=true`／host `cleared=true` になる。途中で終了した保存は、cold復帰時に受理済みの幕を安全な閉状態へ復元し、制御室から再開する。未実行の退出歩行や任意の発見を捏造しない。

## 攻略手順（以下は仕掛けの答えを含む）

1. 初期の影は小さなコートのcast面からできている。レールを端側へ動かし、両窓が灯る広い範囲で「灯りを固定する」。誤答・取消は進行を失わない。
2. 開いた狭い入口を通る。左右の通路のどちらからでも制御室へ行ける。点検歩廊を無視しても必須条件を満たす。
3. 任意で左の点検窓を開き、外の歩廊から実際の床・壁と同寸法の人形を見る。保守取っ手を別に開くと映写機区画への短い経路になる。
4. 囮を使うなら保護ベイで周囲を確認して取っ手を回す。敵が聞ける位置で、その場から出る音を調べている間に別の入口／通路へ移る。目の前で見られている時の無敵操作ではない。
5. 奥の狭い入口から制御室へ入り、来た側の実取っ手を向いて幕を下ろす。閉じた後、向きを変え、自分でサービス出口まで歩く。
