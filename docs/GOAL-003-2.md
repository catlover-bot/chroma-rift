## 描画の修正と観測

nativeRendererFactory.tsは**adapter canvasごと**にfactoryの結果を保持し、configureが再入しても同じrendererを返す。contextや別セッションをまたぐglobal cacheは使わない。constructor自身のgetContextを一時的に観測し、同じreceiver・引数で一度だけ委譲してfinallyで戻す。GLメソッドやThree prototypeは変更せず、初期化失敗前にcontextが得られたかも区別できる。

nativeSceneSession.tsが以下を別々に記録する。

1. RNコンテナのonLayout。
2. constructorのnative context取得とdrawing-buffer寸法。
3. renderer作成・所有権。
4. 実R3F子ツリーのlayout effectによるscene commitment。
5. useFrameのframeCallbacksと、実際の進行計算のsimulationTicks。
6. 実Three renderの呼出し・return。
7. installed native render＋endFrameEXP wrapperのreturn。
8. pixelEvidence（通常章ではnot-sampled）。

render observerをnative wrapperより内側に置く。外側では既存wrapperを正しいreceiverで一度だけ呼ぶ。追加のRAFや手動endFrameEXPを本編へ追加しない。負priority -1のuseFrameは自動renderを無効にしない。シミュレーションのsnapshot公開は同じframeのwrapper return後。失敗したframeの自動移動・印の取得等は巻き戻してpauseし、保存へ公開しない。

draw statsは以前のsimulation前ではなく、実render return後に採取する。scene/camera採取は初回即時、その後は起動中と診断表示中に最大2Hz、通常プレイ中は最大1Hz。sceneSampleRenderReturnがどの描画時点の値かを示すので、停止後に開いた診断でも初期位置を現在位置として誤読しない。診断UI更新は開いている間だけ最大2Hz。GLエラー確認も初回即時、その後は起動中最大2Hz、プレイ中最大1Hzとし、draw直後とnative wrapper return後を区別する。シェーダーエラーは公開hookでその時点に扱う。

native endFrameEXPは提示をキューへ送り、iOSのCADisplayLinkによる実画面の表示は後で行われる。**presentationReturnsはwrapper returnの回数であり、画面に画素が見えた回数ではない。** draw calls、frustum候補も可視画素の保証ではない。

既存DataTextureは128または256の正方形、Uint8 RGBA、全画素alpha=255、sRGB、LinearFilter、mipmapなし。初期生成時にデータを埋めてneedsUpdateを立て、色比較は同じtextureのRGBだけを更新する。scene入場が所有し終了時にdisposeする。確認シーンAではこのtextureを生成せず、無照明材質を先に確認できる。本編の材質・形状・depth規則を推測で一括変更していない。

## 起動・中断・再試行の契約

初期化、scene commitment、first-submitted、ready、failed、closedを分ける。onCreatedだけではreadyにならない。ready前も描画を許可し、入力とゲーム進行を止める。

技術的なreadyには、最新RNサイズとdrawing bufferが正、有効で有限のcamera、正のviewport、default render target、期待するmeshとfrustum候補、有効な支持床、実renderとnative wrapperの完了、既知のshader/GL失敗がないことを要求する。これは画素の意味を確認する判定ではない。

開始から前景・非pause時間で12秒以内に成立しなければ、再試行・ホーム・開発診断がある失敗画面へ移る。背景／pause中は期限を消費せず、復帰で移動量を蓄積しない。再試行は同じ入場で最大2回、明示操作のみ。controller・Canvas・resourcesを作り直し、位置・進行・色比較・設定を保持する。古いready/error/snapshotを拒否する。

同一入場でnative adapterが予期せず交換された場合は、旧rendererのまま続けず、入力を止めて明示的な再試行へ移す。Goal 003.1の終了処理専用rendererはconstructor失敗時だけ使い、readyやゲーム進行へ到達させない。通常のR3F unmountを通してrootを解放する。

## 最初の操作

保存された標準／簡単操作の希望と、有効な操作モードを分けて表示する。減動、読み上げ、文字倍率1.5以上の条件で簡単操作を使う場合は、具体的な理由を設定と診断へ出す。希望やアクセシビリティ設定は上書きしない。

最初はモードに応じて「前へ一歩」またはスティックで小さな光へ近づく1文を表示。対象が視野内にあり遮蔽されていないことを実行列で確認し、遠い時は接近、近いが照準が外れる時は照準を案内する。簡単操作では選択済みの光への視線差から「上を見る／下を見る／左を向く／右を向く」を案内し、下を向きすぎた場合も戻し方を示す。既存の射線・距離を満たすと「しるべを調べる」が使え、成功後は床の輪への短い案内を出す。

ドメインの距離・遮蔽・鍵・扉の条件、章の地形、色比較規則は維持する。新しい自動照準や解答代行は追加しない。約1分で最初の操作を理解できることは設計目標であり、ユーザーテストの実測ではない。

旋回直後は古いcamera行列を無効にするが、次の描画で案内が以前と同じ分類へ戻ると通知が省かれる不具合も再現した。明示的な旋回・既存の照準補助にだけrevisionを付け、次の提示後に案内を再公開する。静止や連続歩行の毎フレームをReact更新へ変換しない。

- A「R3Fの箱・床・壁を確認」: 本編と同じCanvas/bootstrap、固定camera、3個の大きな無照明mesh。テクスチャ・光源依存・入力・保存checkpoint・fogなし。
- Aが見えない場合だけB「箱が見えない：生のGLを確認」: Aをunmountし、別GLView/contextでshader compile/link、三角形draw、1回のendFrameEXPを行う。独立の常時loopは持たない。公開readPixelsが使えれば提示前の中心1画素だけを読む。これはnative compositionの証明ではない。

判別: Bも無地ならcontext／viewport／提示／RN composition、Bだけ見えればR3F／Three bootstrap、Aが見えて本編だけ無地ならcamera／world／material／texture、本編が見えれば最初の操作へ進む。端末ではAが見えるのを確認してから本編のLambert材質とDataTextureを評価する。無根拠な全面DoubleSide、depth無効化、pixelStorei抑制や依存更新は行わない。
