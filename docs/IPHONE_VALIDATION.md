# Goal 004 — iPhoneで操作を確認する

**以下は実施待ちです。** expo-gl入りの既存Development Buildを使います。Goal 004はJS/TS更新で、native依存/設定の変更はありません。全保存のリセットは不要です。

1. 既存Metroを止め、新しいsessionを起動する。

   ~~~sh
   cd /home/mhirotaka/workspace/chroma-rift
   npx expo start --dev-client --tunnel --clear
   ~~~

   CHROMA RIFTを完全終了して開き、新しいMetroへ接続する。
2. 描画の診断でrevisionが `goal-004-drag-first-r1` か確認し、探索へ戻る。最初の部屋の壁・床・入口・しるべの**形**が見えるか確認する。ラベルや背景色だけでは成功にしない。
3. 通常のドラッグ設定で開始する。保存がボタン操作なら最初の一時停止から「ドラッグ操作を試す」。初回の部屋も確かめる場合だけ「章を最初から」を使い、調整/スコア/設定の全消去はしない。導入完了記録は章再開でも保持するため、導入そのものの初見trialには別の未使用テスト保存環境を使う。
4. iOSのReduce Motionを有効にし、ドラッグが使え、装飾的な動きが減るか確認する。ユーザーが歩く/見回す動きは続く。
5. 文字を拡大し、文が折り返され、操作に指が届き、ボタン移動へ勝手に変わらないか確認する。
6. 左の領域に指を置くだけでは動かず、短く/大きくドラッグすると遅く/速く歩くか確認する。リングの外、元の領域の外へ出ても保持し、離すとすぐ止まるか確認する。
7. 左をずらしたまま保持し、右で見回す。右だけ/左だけを交互に離して、残る指の操作が続くか繰り返す。中央をまたいでも役割が交換されないか見る。
8. 両指の操作中に別の指で一時停止する。再開時に残った指で動き出さず、新しく触ってから動くか確認する。
9. 攻略を読まず、光のしるべへ歩いて見回し、文脈付きボタンで調べる。所要時間と迷った箇所を記録する。10〜15秒で歩行/見回し、30〜45秒で最初の操作は目標で、制限ではない。
10. 床の輪→装置→重なる鍵の目的が分かり、解けるか確認する。条件不足の理由、遠い対象への接近案内、壁越しには使えないことも見る。
11. 「色を比べる／色を戻す」を押し、カメラ回転や歩行を誤って始めないか確認する。sceneから指をドラッグしてボタン上で離しても操作されないか確かめる。
12. 背景/復帰、ホーム/再入場を3回行い、操作方式を2回切り替える。残った入力や失敗画面がなく、保存位置と部屋が保持されるか確認する。
13. 明示的なボタン操作とVoiceOverの移動/旋回/調べるが使えるか確認する。VoiceOverを終えると、保存したタッチ操作に戻るか確認する。アクセシビリティ機能を無効にすることを解決策にしない。
14. 第二の封印後に帰路と入口の変化を確かめ、最後の扉を開いて自分で歩き、結末へ到達する。
15. 操作中の不快感を記録し、感じたら中止する。医療的な試験とは扱わない。

追加確認は320×568、390×844、430×932相当の論理サイズ、文字拡大、safe areaを含める。自動layout/component testを通過していても、実際の文字や親指位置はこのtrialで確かめる。

共有用captureは**45〜90秒程度**で、両指ドラッグ→片方ずつ離す→しるべの操作→一時停止/再開が分かる部分を一度撮る。指の位置が録画に映らなければ短く状況を書き添える。ネットワークURL、QR、account識別子を映さない。チェック全項目を繰り返す長い録画は不要。

## 部屋の形が見えない場合

1. 準備中/失敗画面または一時停止から「描画の診断」→「診断をコピー」。
2. 「R3Fの箱・床・壁を確認」で3つの形が見えるか確認。
3. 箱も見えない場合だけ「描画の診断」→「箱が見えない：生のGLを確認」で橙色の三角形を確認。
4. 見え方と診断を記録し、「探索へ戻る（進行を維持）」へ戻る。

診断のコピーはlocalのみで、外部へ自動送信しない。失敗時の再試行は明示操作で最大2回。警告と実際の形の表示不良を分けて記録する。根拠・自動検証・未確認範囲は[GOAL-004.md](GOAL-004.md)に記録する。
