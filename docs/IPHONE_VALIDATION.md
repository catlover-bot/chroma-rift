**以下は実機未実施の手順。** コード・native 境界・ブラウザーの描画検査を、実機表示、実指、知覚、怖さ、実聴、性能の確認結果に置き換えない。依存 / native 設定を変えず、expo-gl と expo-audio を含む既存 Development Build が新版 JS と同梱素材を Metro から読み込む。今回のための EAS Build、認証、アプリ削除、全データ reset は行わない。

```sh

```

既存の同ポートの Metro が動いている場合は先に終了する。接続後は表示された壁・床・装置と「描画の診断」からコピーした revision を記録し、revision `goal-008-perceptual-r1` を確認し、ロード文言だけで表示済みとしない。録画や診断に URL / QR / account 識別子を含めない。

## 最初の 5 分

1. iPhone model / iOS / Build 版 / revision / 普段の明るさ / True Tone / Night Shift / fontScale / 消音と音量を記録する。初回の 3 問はスキップできる。ホーム「新しい展示室を始める」、または旧クリア結果から章だけ再プレイを選ぶ。
2. 非常灯と出口盤を調べ、色の展示を普段の条件で見て任意に比べる。前後色の期待を教えず、分かりにくい場合も進める。
3. 固定した凹面仮面を正面と横から見る。窓を開閉し、仮面自体の回転や差替えがないか確認する。ハイブリッド掲示へ近づき離れ、どの図柄が読めたか自由記述する。同じ画像かを確認し、錯視を感じないことを不合格にしない。
4. B または C を操作する。B は 0→1→2 枚の案内、同じ灰色の中心、独立した「比べる」。C は円盤の縁、0..3/3 と独立した引き出し操作。通常中央に線・面・照準がなく、補助だけ明示されることを確認する。電源を取った後の予兆と横切りを見たか、気付かなかった場合はそのまま記録する。
5. pause→発見メモ。発見した項目のみ出て、それぞれ実際に比較を操作できるか確認する。仮面の比較視点を横へ動かして閉じ、本編の位置と向き・展示体が進まず戻ることを確認する。音は任意で、いつでも stop。音 off / 演出音 off / 控えめでは再生しない。

5 分は観察の区切りで、攻略の時間制限・実測所要時間ではない。強い照明、長い凝視、片目を隠すこと、ヘッドフォンを要求しない。不快なら pause・退出できる。

## 最後までの確認

- B→C と C→B をそれぞれ解き、別操作で二個を取り、出口盤で電源を接続する。A / D は新版の必須条件・結果に出ない。

- 開いた通路で予兆・姿を見て、棚の陰へ退く→待つ→抜ける。見通しと身体 / 衝突が一致し、突然の移動・不意の消失がないか記録する。控えめでは同じ経路を危険なしで進められる。
- 安全な敷居まで歩き、「扉を閉める」を押す。ドラッグ操作でも押せること、閉扉が見え、短い衝撃音の後に静まり結果へ進むことを確認する。閉扉後に捕まらず、再開してクリアが戻らない。

12. 足音が実移動だけで鳴り、壁へ押し付けるだけでは鳴らない。操作音/解錠/環境音、master/環境/効果の音量、silent switchを確認。pause/background/描画失敗/退出で止まり、再開時に過去の音をまとめて鳴らさない。

初回は再入場・背景復帰を3回、継続性能確認では10回行う。renderer/context/texture/audio playerが増え続けないかを実測し、通常の開発実行・録画あり・本番相当を分けて記録する。60fps、実機の音量/発熱、錯視の強さ、8〜12分の初見目標は自動テスト結果から推定しない。

不快感があればpause・退出し、その状況を記録する。強い明るさ、ヘッドフォン、片目を隠すこと、特殊な目の状態は要求しない。短い録画を使う場合は指の操作説明を添え、URL/QR/account識別子を映さない。アプリ内pauseと開発ランチャーのアイコンを区別する。

### 表示できない場合

準備中/失敗/一時停止から「描画の診断」→「診断をコピー」。R3Fの箱・床・壁、それも見えない時だけ生のGLの橙色三角形を確認する。「探索へ戻る（進行を維持）」で戻る。手動再試行は最大2回。取得した診断と実際の画面を分けて記録する。
